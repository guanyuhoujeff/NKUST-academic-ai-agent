# 寫文獻回顧

文獻回顧不是把每篇摘要排在一起，而是**按主題**把幾篇放在一起比較：誰發現了什麼、哪裡一致、哪裡不同、還有什麼沒人做。
它也是最容易被 AI 寫出「看起來很像、其實沒出處」的東西，所以這個 skill 的核心是：**每一句都要追得回文獻卡的某一頁。**

這個流程有一支「流程管家」程式幫你記住做到哪、下一步是什麼，也負責逐句檢查。

## 唯一要記住的規則

**每一輪對話，你的第一個動作都是執行這一行，然後照它印出來的指示做：**

```
python .opencode/skills/write-review/scripts/review.py next
```

（Windows 的 `python` 無效時改用 `py`。）

**不要憑記憶跳到後面的步驟**——每一關都有程式把關，跳關會被擋下來。

## 流程全貌（給你和使用者看的地圖）

| 關 | 做什麼 | 過關條件 | 指令 |
|---|---|---|---|
| 1 | 和使用者定**研究問題** | 一句完整的問題 | `review.py question "…"` |
| 2 | **逐篇初篩**：程式一篇一篇把文獻卡摘錄送給模型，問它和研究問題相關或不相關，相關的進暫存清單。**你不用自己判斷** | 每一篇都判斷過（程式分批跑，每批約 90 秒） | `review.py screen` |
| ★ | 把初篩結果（相關／不相關＋理由）給使用者看，**停下來等他確認**，他可以撈回或剔除 | 使用者說可以 | `review.py include／exclude`、`approve` |
| 3 | **第二輪**：只讀暫存清單的全文，決定哪些真的用、怎麼分組，寫 `plan.md` | 按主題分節、每個主題節至少 2 張卡、最後一節是「研究缺口」；暫存清單每一張都要有去處（放進某節，或寫進「暫存但不採用」附理由） | `review.py check-plan` |
| ★ | 把 `plan.md` 貼給使用者，**停下來等他確認** | 使用者說可以 | `review.py approve` |
| 4 | 照架構寫 `review.md` | 每一句都有（作者, 年，第 N 頁）；頁碼、數字都在文獻卡找得到；沒有簡體字 | `review.py check` |
| 5 | 程式從文獻卡的 APA 欄位產生參考文獻，附在最後 | — | （`check` 通過時自動做） |

★ 是要停下來等使用者的地方。

例外：使用者明說「全部交給你、不用問我」，才可以執行 `review.py auto "使用者原話"` 跳過停頓點。

## 初篩需要 Ollama 的 API key

初篩是程式直接呼叫 Ollama，所以要拿得到 key：環境變數 `OLLAMA_API_KEY`，或工作資料夾裡的 `.ollama_key` 檔（內容只有 key 一行）。都沒有時，程式會告訴你怎麼請使用者設定。**不要叫使用者把 key 貼在對話裡。**

為什麼不讓你自己判斷？實測時，被要求「一篇一篇看」的 AI 會自己寫迴圈、用關鍵字批次判斷，結果漏掉最重要的文獻。交給程式逐篇問，才保證每一篇都真的被看過。

## 三條規則

1. **內容只能來自 `notes/` 的文獻卡。** 文獻卡沒寫的發現、數字、結論，不可以出現；文獻卡寫「文中未述」的，就不可以寫成有。
2. **每一句都要有出處，頁碼照文獻卡上標的抄。** 數字要和文獻卡一模一樣，不可以估算、四捨五入或換算。
3. **不要自己寫參考文獻。** 程式會從文獻卡產生；你寫的會被蓋掉。

## 產出物

| 檔案 | 內容 |
|---|---|
| `screening.md` | 初篩紀錄：每一篇的判斷（相關／不相關）與理由，程式產生 |
| `plan.md` | 研究問題、讀者、暫存但不採用的卡與理由、分節表（節｜主題｜文獻卡｜這一節要回答的問題） |
| `review.md` | 文獻回顧本文＋程式產生的參考文獻 |

## 做完之後要提醒使用者

程式只能檢查**出處、頁碼、數字有沒有對上**。一句話的**意思有沒有被寫歪**（例如「誤差低於 0.5%」寫成「精度高於 0.5%」），程式抓不到，要使用者自己對照文獻卡讀一遍。
